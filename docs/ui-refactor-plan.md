# 桌面坞 DeskDock · UI 重构调整计划

基线 v1.2.1 ｜ 审查日期 2026-11-13 ｜ 范围：`src/renderer/*`、`src/main/main.js` 布局常量、`src/main/store.js` 默认值
结论：**保留现有信息架构，重做视觉系统与状态层；不重做品牌。**

---

## 0. 摘要

当前界面能完成全部任务，问题不在"功能缺失"，而在**没有系统**：10 档圆角、7 档字号、5 处硬编码常量、hover 独占的隐藏操作、以及三处真实缺陷（设置不即时生效、整表重绘丢焦点、删除副本无确认）。

本次重构做四件事：

1. **修 P0 缺陷**，让改动能被验证（否则调完主题看不见效果）。
2. **建令牌层**，把颜色/字号/间距/圆角/阴影收进 `tokens.css`，删掉一次性数值。
3. **重排结构**：顶栏 4 图标改 3 个 + 溢出菜单；分类头排序与折叠分离；磁贴去掉灰底板；空分类给真实投放区；设置拆 4 个页签；「每排图标个数」由内容推导改为用户指定，面板与弹窗宽度因此固定可预期。
4. **补状态与可达性**：hover/active/focus/selected/loading/missing/empty 全定义，键盘可完成主路径。

不改：分类/条目数据模型、拖拽换边、贴边感应、图标提取、导入与备份流程。

## 2. 路线决定

### 2.1 分支与模式

- **分支：product**。交付物是可交互的常驻工具界面，验收标准是操作可完成、状态可恢复，不是静态视觉稿。
- **模式：紧凑型桌面工具（operational utility）**，取 Devtool 模式的交互优先级（快捷键、焦点、稳定尺寸），不取其视觉（不做 IDE 式多面板）。

候选模式打分（0–2，仅记录判断依据）：

| 模式 | 任务契合 | 使用场景 | 密度 | 设备 | 品牌约束 | 实现风险 | 合计 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 紧凑型桌面工具 | 2 | 2 | 2 | 2 | 2 | 2 | **12** |
| 运营后台 / 仪表盘 | 1 | 1 | 1 | 2 | 2 | 1 | 8 |
| 移动 / 触屏优先 | 1 | 1 | 1 | 0 | 2 | 1 | 6 |
| 品牌 / 营销页 | 0 | 0 | 0 | 2 | 2 | 1 | 5 |

### 2.2 视觉谱系

- **主线：Windows 11 Fluent**。理由：坞常驻桌面、与资源管理器同屏，必须像系统的一部分而不是一个网页挂件。取它的分层中性色、1px 发丝线、4/8 间距、收敛圆角、Segoe UI Variable、单一强调色。
- **辅线（仅交互）：启动器 / 命令面板**。理由：高频动作是"找图标 → 打开"，搜索应当是一等入口而不是隐藏面板。只取键盘模型与搜索优先，**不取**深色玻璃 + 霓虹描边 + 超大快捷键提示那套皮肤。
- **不复制**：macOS Dock 的放大/倒影；玻璃拟态全屏模糊；紫色渐变 AI 风；营销页大字号。

### 2.3 五条视觉原则

1. **图标是主体，容器退到最轻**：去掉图标灰底板，只保留 hover 表面与 1px 内发丝线。
2. **一条 4px 节奏**：4/8/12/16/20；满足"元素内 < 相关项 < 组间 < 区段"。
3. **一个强调色，只表示"可操作/当前/焦点"**：不用它装饰分类，分类色只做 6px 圆点与空态着色。
4. **圆角四档、阴影两级**：6/8/10/14，禁止出现 5/7/9/11/12。
5. **文字三档、字距 0、对比度 ≥4.5:1**：11/12/13，正文不小于 11px。

### 2.4 五条交互原则

1. **hover 才能看到的操作，必须有常驻或键盘等价路径**（`⋯` 常显 40% 不透明度，聚焦即 100%）。
2. **键盘可完成主路径**：Tab 遍历、方向键在网格内移动、Enter 打开、Esc 逐层退出、Ctrl+F 搜索、Ctrl+, 设置。
3. **拖拽必须有目标反馈**：分类高亮 + 插入线；投放区不可用时给禁止光标。
4. **破坏性动作命名对象与后果**，可恢复的给撤销；不可恢复的必须二次确认。
5. **状态切换不改变尺寸**：hover/focus/loading/missing 都不移动相邻元素。

### 3.4 圆角、描边、深度、动效

- 圆角：`--r-xs 6`（角标、chip）、`--r-sm 8`（按钮、输入、行）、`--r-md 10`（磁贴、菜单）、`--r-lg 14`（面板、弹窗）、`999`（圆点/开关）。**只有这五档。**
- 描边：默认 1px `--line`；可交互元素 hover 升到 `--line-strong`；不使用彩色描边做装饰。
- 深度：只两级。面板 `0 4px 16px rgba(0,0,0,.28)`；浮层/弹窗 `0 16px 40px rgba(0,0,0,.42)`。列表行、磁贴、设置行一律无阴影（用表面差与发丝线）。

## 4. 结构调整

### 4.1 顶栏：4 个平级图标 → 3 个 + 溢出

现状：`搜索 / 导入 / 图钉 / 设置` 四个 28px 图标等权，左侧品牌区在 3 列面板被压到 67px。

改为：

```
[mark 24] 桌面坞            [搜索] [图钉] [⋯]
```

- 品牌区只留标记 + 文字，**计数移到页脚**，解决最窄档（4 个/排 = 338px）截断。
- `⋯` 菜单：从桌面导入… / 新建分类… / 分隔 / 设置… / 退出。导入从"常驻按钮"降为"低频命令"，首次与空态另有主 CTA。
- 图钉保留在顶栏（高频切换），设置同时保留 `Ctrl+,` 与托盘入口，避免降级成"藏起来的功能"。
- 搜索：≥5 个/排时是行内输入框（宽 160–180），4 个/排时是图标按钮，点开后覆盖顶栏第二行，不再挤占列表高度。
- 交互修正：顶栏拖动排除 `input`/`button`/`[role=button]`（现有 `renderer.js:977` 只排除 `button`，加输入框会误触拖动）。

### 4.2 分类头：把"折叠"和"排序"分开

现状顺序：`⠿ 圆点 名称 计数 ……… ⋯ ▾`，箭头在最右，且 `⋯` 只在 hover 出现。

改为（32px 高，吸顶）：

```
[▾ 12] [● 6] 编程开发  11 …………… [⠿ 16(悬停)] [⋯ 24]
```

- 箭头移到最左：展开状态与名称相邻，扫读一次完成。
- `⋯` 常显 40% 不透明度，hover/聚焦 100%——满足"hover 不是唯一入口"。
- 整行可拖拽（5px 阈值区分点击折叠），`⠿` 只在 hover 显示，作为可拖的提示而非唯一热区。
- 键盘等价：分类头是 `<button aria-expanded>`；`⋯` 菜单增加「上移 / 下移」，让无法拖拽的用户也能排序。
- 吸顶：`position: sticky; top: 0; z-index: 2; background: var(--surface-1)`，靠 1px 下边线与内容分界。12 个分类、93 项时可随时知道自己在哪一组。

### 4.3 磁贴与状态

- 去掉 `.ico` 的灰色底板，改为 `background: var(--icon-plate)`（深色透明，浅色 4.5% 保护纯白图标）。
- 标签 11px/1.25、固定 2 行块高 28，行高一致；hover 时标签升到 `--text-1`。
- missing：**只把图标降到 55%**，标签保持可读；右上角 12px `--warn` 角标 + tooltip 说明"文件已丢失，可在数据 → 修复失效项处理"。
- loading：44×44 圆角占位（`--surface-2` + 1.2s 呼吸），图标到达后 120ms 淡入；**取消"先显示首字母再换图"的闪跳**，仅在请求结果为空时才显示首字母。
- 冷却：保留 2s 行为（防重复启动），视觉改为压暗 55% + 2px 进度环；`backdrop-filter` 从 93 个磁贴上移除（只影响一个，但避免合成层开销）。
- 拖拽插入线：改为 2×24 的竖条（横向坞为 24×2），贴在目标位置，不再跨整行。

### 4.4 空状态

- 面板级（0 条目）：居中标记 + 一句说明 + 主按钮「从桌面导入」+ 次按钮「把 .lnk 拖进来」。
- 分类级（0 条目）：56px 高、满宽虚线投放区，居中「拖到这里」；dragover 时变 `--accent` 边 + `--accent-weak` 底。这是 P0-4 的修法。

### 4.5 搜索：从"过滤"到"结果视图"

- `Ctrl+F` 打开，输入即出结果；结果替换列表，不再靠"强制展开所有分类"。
- 结果行 40px：24 图标 + 名称（命中片段 `<mark>` 高亮）+ 右侧分类 chip。

- 中文输入法组合期不触发搜索（`compositionstart/end` 守卫）。

### 4.6 设置：单页长滚 → 4 个页签

```

```

- **外观**：主题（跟随系统/浅/深）· 图标大小 · 磁贴宽度 · **每排图标个数（4–10，默认 6；步进器 `− 6 +`，改完面板宽度立即跟着变）** · 显示名称 · 点击冷却（开关 + 滑杆）· 实时预览（3 个示例磁贴）。

## 6. 主进程与样式常量同步表

这是本次最容易翻车的地方：面板宽度由主进程算，网格由 CSS 排，两边对不上就会出现 2px 抖动或横向滚动。

### 6.1 必须同步的常量

| 常量 | 位置 | 现值 | 新值 | 原因 |
| --- | --- | --- | --- | --- |
| `PAD` | `main.js:15` | 18 | 18 | 阴影需要 ≥18，不动 |
| `--pane-pad` | `styles.css:9` | 18 | 18 | 必须等于 `PAD` |
| `PANEL_CHROME` | `main.js:20` | 30 | **32** | 边框 2 + 列表左右 24 + 滚动条 6 |
| `COL_GAP` | `main.js:19` | 2 | **6** | 等于网格列间距 |
| 滚动条 | `styles.css:181` | 8 | **6** | 计入 `PANEL_CHROME` |
| `tileSize` 默认 | `store.js:250` | 74 | **72** | 10 个/排总宽 806，1366 屏可容纳 |
| `tileSize` 夹取 | `main.js:141` / 设置滑杆 | 62–104 | 60–104 | 两处一致 |
| `iconSize` 默认/范围 | `store.js:249` / `renderer.js:433` | 44 / 32–64 | 不变 | — |
| 列表内边距 | `styles.css:178` | 8/10 | **8/12** | 与 `PANEL_CHROME` 对齐 |
| `MIN_COLS` / `MAX_COLS` | `main.js:17-18` | 3 / 10 | **4 / 10** | 改为夹取 `columns` 设置，不再夹内容数 |
| `columns` 默认/范围 | `store.js` / 设置步进器 | 无 | **6 / 4–10** | 新增「每排图标个数」，决定面板宽度 |

### 6.2 宽度复核

- 面板宽 = `32 + n×tile + (n−1)×6`，`n` 取设置里的「每排图标个数」（4–10，默认 6），**不再由内容决定**
- 4 × 72 = **338**；6 × 72 = **494**；10 × 72 = **806**；10 × 104 = **1126**（窗口 1162，1366 屏可用 1306，余量 144）
- 弹窗宽 = 面板宽 − 36（遮罩左右各 18）：4 个/排 → 302，默认 6 个/排 → **458**，10 × 104 → 1090。原来的 460 目标值就是默认 6 个/排，由设置决定，而不是给卡片写死上限
- 顶栏在最窄档（4 个/排）时可用宽度 = 338 − 14（左内边距）− 24（标记）− 8（间距）− 40（文字）− 8 − 100（3×32+2×2）− 8（右内边距）= **136px 余量**，结论：放得下且宽裕；现状 4 按钮时为 −33px，必然截断。

### 6.3 改配置时的联动

`columns` 或 `tileSize` 变化 → `relayout()`（`main.js:606` 的触发条件要把 `columns` 加进去）→ 主进程按 `panelWidthFor(columns)` 重设窗口 → 渲染层 `dock:layout` → `--cols` 与 `data-fit` → `applySettings()`。任何新增的尺寸项（如新的列表内边距）都必须进 `PANEL_CHROME`，否则右侧会被裁掉一条。

老配置没有 `columns`：在 `normalize()` 里按旧规则算一次 `clamp(maxCategoryCount(), 4, 10)` 写回，避免升级瞬间被压回默认 6 个/排。之后宽度只由用户改，不再随内容跳变。这次快照只改一次：原先 3 条目/排的用户会从 260 变 338（+78，因为最小档提到 4），其余基本持平。

连带清理：`store.maxCategoryCount()` 改完后只剩迁移这一处调用（`main.js:136` 不再用），不要留成死函数。

## 8. 风险与未决

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 去底板后浅色主题丢图标 | 很多 Windows 图标是白色或透明底 | `--icon-plate` 浅色保留 4.5% 底 + 1px 发丝线；用真实图标集（非字母兜底）回归 |
